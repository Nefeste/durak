# Как устроено

Документ описывает то, что **будет** в коде; когда код появится — то, что есть, и расхождение правится в том же
коммите. Почти всё копируется из «Нард» (ADR [0001](adr/0001-copy-from-nardy.md)): каждый скопированный файл
начинается строкой `// из nardy: <путь> @ <коммит>`. Ниже — что берём как есть, что меняем и что новое.

```
  телефон (Android, Expo SDK 57)                      сервер (машина сайта, Россия)
┌──────────────────────────────────┐             ┌────────────────────────────────┐
│ App.tsx   переключатель экранов  │   HTTPS     │ nginx — TLS, durak.gornitsa.games│
│ src/game/     стол и партия      │ ──────────► │ Bun: server/src/               │
│ src/screens/  меню, разбор, ...  │  команды    │   http.ts   маршруты /v1/*     │
│ src/state/    сессия, сеть,      │             │   live.ts   события по местам  │
│               статистика         │ ◄────────── │   core.ts   столы, колода, часы│
│ src/money/    покупки, реклама   │  WebSocket  │   view.ts   что видит место    │
│ src/bot/      боты, разбор       │  (вид места)│   тот же src/engine            │
│ src/engine/   ПРАВИЛА ◄──────────┼── импорт ───┤                                │
└───────┬──────────────┬───────────┘             └───────┬────────────────────────┘
   RuStore Pay    Рекламная сеть                  SQLite (WAL) ──► копия раз в сутки
```

## Главная мысль: партия — расстановка, колода и список действий

Партия целиком описывается **расстановкой** (версия свода, вариант, места, кто ходит первым), **порядком колоды**
и **списком действий** (ADR [0002](adr/0002-game-as-action-list.md)). Движок детерминирован и случайности не знает:
порядок колоды ему передают.

- **Сохранение** — расстановка, колода и действия; восстановление — переигрывание.
- **Онлайн** — те же данные, но колоду и действия хранит сервер; телефон получает **вид своего места**
  (ADR [0008](adr/0008-server-per-seat-views.md)), а колоду — только после партии, для проверки.
- **Сервер проверяет действие**, применяя его тем же движком.
- **Разбор и статистика** получаются из записи.
- **Цена:** изменение правил ломает старые записи, поэтому у партии есть версия свода (ADR [0003](adr/0003-rules-in-record.md)).

## Движок `src/engine/`

Чистый TypeScript: без React, `Date.now()` и `Math.random()`. Один код для телефона, сервера, ботов, решателя
концовки и инструментов.

| Файл | Что |
|---|---|
| `cards.ts` | карта — число 0…35 (`масть × 9 + достоинство`), старшинство, «бьёт ли», запись `7♥` |
| `rules.ts` | свод `durak-rules-v1` и настройки стола (вариант, места) |
| `state.ts` | позиция: руки, прикуп, козырь, стол (пары «атака — защита»), сброс, кто ходящий и отбивающийся, кто сказал «пас», вышедшие, номер отбоя |
| `actions.ts` | действия: `attack`, `throwIn`, `beat`, `transfer`, `take`, `give` (вдогонку), `pass`, `done` |
| `legal.ts` | все законные действия места и **причина запрета** для любого незаконного (`reasonOf`) |
| `apply.ts` | `apply(state, seat, action)` → новая позиция или ошибка; конец отбоя, добор, выход, конец партии |
| `observe.ts` | `observe(state, seat)` → **наблюдение** места: всё, что видит игрок на этом месте (ниже) |
| `deck.ts` | порядок колоды из зёрен (`durak-deck-v1`, [спецификация](specs/2026-11-v1.md), «Колода»), SHA-256 и HMAC |
| `replay.ts` | партия из записи; сверка записи с колодой (для проверки на телефоне) |

### Наблюдение — граница между правдой и игроком

`observe(state, seat)` возвращает: свою руку; козырную карту и сколько карт в прикупе; стол; сброс (какие карты в
нём — их видели все); карты, которые каждый соперник **взял в открытую** и ещё не сыграл; сколько карт у каждого;
кто ходит, кто отбивается, кто сказал «пас»; историю отбоев. И больше ничего.

Это **единственный вход** для ботов, подсказки, экрана партии и сервера, когда он отдаёт вид места
(ADR [0005](adr/0005-bot-observation.md), [0008](adr/0008-server-per-seat-views.md)). Тест строит пары позиций с
одним наблюдением и разными скрытыми картами и требует от каждого бота одного и того же действия.

## Слои приложения

| Папка | Что | Откуда |
|---|---|---|
| `src/engine/` | правила, колода, наблюдение | новое |
| `src/bot/` | уровни, поиск по раскладам, точный расчёт концовки, разбор, «почему», задача дня; `think.ts` — расчёт кусками по ≤12 мс | `think.ts`, устройство уровней и разбора — из «Нард»; расчёт — новый |
| `src/render/` | карты кодом (Skia): лицо, рубашка, индексы, орнамент; раскладка стола и руки (`layout.ts` — чистые функции) | новое |
| `src/game/` | экран партии: один холст Skia со всеми картами, анимация Reanimated, касания Gesture Handler; панель и кнопки — React Native | новое |
| `src/state/` | живая партия (`GameSession`), сохранения, настройки, история, статистика, рейтинг тренировок; онлайн: `protocol.ts`, `net.ts`, `live.ts`, `online.ts`, `quick.ts`, `invite.ts` | из «Нард», протокол — свой |
| `src/money/` | реклама и покупки: `ads.ts` (правила частоты), `rights.ts`, порты и подделки для веба | из «Нард» как есть, RuStore Pay — из `@gornitsa/kit` |
| `src/screens/` | меню, выбор стола, онлайн, разбор, задача дня, статистика, правила, магазин, настройки | разметка — своя, диалог и кнопки — из «Нард» |
| `src/ui/` | палитра (токены брендбука), тема, кнопки, диалог, звук и вибрация, «Меньше движения» | из «Нард» и брендбука |
| `src/i18n/` | все строки | механика — из «Нард» |

Экраны переключаются состоянием, без роутера, как в «Нардах». `App.tsx` обрабатывает «назад» и одну ссылку —
приглашение за стол.

### Рисование

Один холст Skia на весь стол (ADR [0010](adr/0010-cards-in-code.md)): 36 лиц и рубашка рисуются кодом один раз в
картинки (`Picture`) при запуске и при смене оформления; каждая карта на столе — картинка с положением и поворотом
из общего значения Reanimated. Так 36 карт в полёте — один кадр холста, без 36 компонентов React. Тот же приём
(`drawAtlas`, картинка на кадр) проба `Nefeste/probe-3d` держала 121 кадр на телефоне владельца
([ADR 0024 устава](https://github.com/Nefeste/gornitsa/blob/main/adr/0024-3d-phone.md)).

### Как ходят действия

1. Касание выбирает карту; экран спрашивает у движка законные места для неё (`legal.ts`) и подсвечивает их.
2. Действие — `session.act(action)`: с ботами — сразу в движок и на диск; онлайн — `POST` с номером действия.
3. Боты думают во время паузы перед своим действием, кусками (`think.ts`), интерфейс не замирает.
4. Действия соперников и ботов показываются тем же кодом, что свои.
5. **Подкидывание сразу многими.** Атакующих может быть до трёх. С ботами порядок такой: ходящий, затем по
   часовой стрелке. Онлайн сервер принимает первое пришедшее действие и отвечает остальным `409 stale`
   с новым видом стола.

### Откуда берётся колода

| Режим | Кто тасует | Как проверить |
|---|---|---|
| с ботами, задача дня | телефон, **в момент раздачи**, криптографическим генератором `expo-crypto` | будущих карт не знает никто, ботам колода не видна (тест) |
| онлайн | сервер: HMAC-SHA-256 от своего зерна и зёрен всех телефонов стола | отпечаток зерна — до раздачи, зерно — после партии; телефон пересобирает колоду и сверяет каждую карту, которую видел |

## Сервер

Копия сервера «Нард»: один процесс Bun за nginx на машине сайта в России, база SQLite (WAL), команды — HTTP,
новости — WebSocket, при фильтрации — опрос раз в секунду. Адрес — `durak.gornitsa.games`. Протокол —
[`03-server-api.md`](03-server-api.md), данные — [`04-data-model.md`](04-data-model.md).

Что новое по сравнению с «Нардами»:

- **Скрытые карты.** В нардах всё на доске видно обоим; здесь сервер знает руки всех, а отдаёт каждому только его
  вид (`view.ts`, тот же `observe`). События рассылаются **по местам**: каждое соединение получает событие,
  собранное для его места. Тест обходит все маршруты и события и проверяет, что ни одно не несёт чужой руки и
  порядка прикупа до раскрытия.
- **2–4 места** за столом вместо двух; зёрна всех мест — в колоде.
- **Очередь действий.** Несколько атакующих могут подкинуть одновременно; сервер применяет действия по одному в
  порядке прихода, номер действия делает повтор безопасным.
- **Бот за столом с друзьями** — на сервере, тот же код `src/bot/` уровня «Средний» и выбранных уровней;
  он получает только наблюдение своего места.
- **Таймер «бито».** После последнего покрытия сервер ждёт 1,5 с, прежде чем закрыть отбой, даже если подкинуть
  никому нечем: иначе мгновенное «бито» выдаёт, что у соперников нет нужных карт.

Без изменений: профиль — ключ устройства и ник (ADR 0007 «Нард»), столы по коду и ссылке, быстрая игра и
Glicko-2 (только один на один), фразы, жалобы, сроки хранения, копия базы раз в сутки, страницы `/privacy`,
`/delete`, `/fair`, `/t/<код>`.

## Сборка

Как в «Нардах»: Expo SDK 57, React Native 0.86, Hermes; `android/` создаёт `expo prebuild` в CI; APK — на тег
(`gornitsa-kit`). Нативные SDK: RuStore Pay (плагин `@gornitsa/kit`), Yandex Mobile Ads, RuStore Review (модуль из
«Нард»), Skia, Reanimated, Gesture Handler. Сборки две: `rustore` и `other` — как в «Нардах».
