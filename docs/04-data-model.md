# Данные

## Движок

### Карта

Число `0…35`: `карта = масть × 9 + достоинство`. Масти: 0 ♠, 1 ♣, 2 ♦, 3 ♥. Достоинство: 0 — шестёрка … 8 — туз.
Запись для людей — `6♠`, `10♥`, `В♣`, `Д♦`, `К♥`, `Т♠` (русские индексы, ADR [0010](adr/0010-cards-in-code.md)).
Порядок мастей нужен только для «младшей карты» при выборе первого хода ([`08-rules.md`](08-rules.md), п. 3).

### Позиция

Код — `src/engine/types.ts`; здесь коротко.

```ts
type State = {
  rules: RuleSet;             // свод: id 'durak-rules-v2' (или v1), пределы атаки, firstBoutTransfer, order
  variant: 'podkidnoy' | 'perevodnoy'; seats: number;   // 2..4
  hands: number[][];          // руки по местам
  talon: number[];            // колода сверху вниз; последний — козырь
  trump: number;              // козырная карта (масть = козырь)
  table: [number, number | null][]; // пары «атака — защита»
  discard: number[];          // сброс
  openly: number[][];         // по местам: карты, взятые в открытую и ещё не сыгранные
  starter: number;            // кто начал отбой — для добора после перевода
  attacker: number; defender: number; passed: boolean[];
  boutLimit: number;          // предел карт атаки этого отбоя
  bout: number;               // номер отбоя с нуля
  out: number[];              // порядок выхода
  phase: 'bout' | 'giving' | 'end';
  result: null | { fool: number | null; draw: boolean };
};
```

### Действие

```ts
type Action =
  | { type: 'attack' | 'transfer'; cards: number[] }   // одна или несколько одного достоинства
  | { type: 'throwIn' | 'give'; cards: [number] }       // подкинуть и вдогонку — по одной
  | { type: 'beat'; card: number; on: number }
  | { type: 'take' | 'pass' }
  | { type: 'resign' };                                  // сдаться — правило приложения, 08-rules.md п. 8
```

### Запись партии

```ts
type GameRecord = {
  v: 1;                       // номер формата записи
  rules: RuleSet;             // { id: 'durak-rules-v2', …, order: 'queue' } или ровно RULES_V1 («кто успел»)
  variant: 'podkidnoy' | 'perevodnoy';
  seats: { kind: 'you' | 'bot' | 'human'; level?: Level; name?: string }[];
  first: number;              // кто ходит первым
  firstWhy: 'lowestTrump' | 'lowestCard' | 'afterFool';
  deck: number[];             // 36 чисел — порядок колоды
  source: { kind: 'phone' } | { kind: 'server'; commit: string; seed: string; seeds: string[] };
  actions: { seat: number; action: Action; at: number }[]; // at — мс от начала партии, для разбора и темпа
  result: null | { fool: number | null; draw: boolean; order: number[]; resigned?: number[] };
};
```

Настройка стола «Подкидывать» (ADR [0013](adr/0013-throw-order.md)) — в `rules`: «по очереди» — `RULES` (`id:
'durak-rules-v2', order: 'queue'`), «кто успел» — ровно прежний `RULES_V1` (`id: 'durak-rules-v1'`, поля `order`
нет). Записи, сохранения, история и задачи дня прошлых версий — все `durak-rules-v1` и переигрываются «кто успел», как
их и играли: ни миграции, ни нового ключа (`knownRules`, `orderOf` в `src/engine/types.ts`). Настройка игрока —
`durak.settings`, `throwOrder` (`'queue'` по умолчанию; в строке прошлых версий её нет — по умолчанию).

Сдача ([`08-rules.md`](08-rules.md), п. 8): в позиции — `resigned` (по порядку) и `buried` (их карты рубашкой вверх,
в наблюдении их нет, `allCards` их считает); в наблюдении — `resigned`, только когда кто-то сдался (иначе поля нет, и
наблюдение то же, что у версий до сдачи); в итоге — `resigned`. Места итога — `placesOf`, проиграл ли место — `lostBy`
(`src/engine/types.ts`). С ботами действия ботов, доигравших без вас, тоже в записи.

Восстановление — переигрывание `actions` по `deck`. Запись с ботами хранит колоду с самого начала — это и есть
правда партии; ботам её не передают (ADR [0005](adr/0005-bot-observation.md)).

## Телефон

AsyncStorage, ключи `durak.*`, как в «Нардах»: идущая партия (`durak.game`), история последних 200 партий
(`durak.history`), настройки (`durak.settings`), профиль онлайна (`durak.device`, `durak.name`), права покупок
(`durak.rights`), задачи дня (`durak.daily`), счётчики своей статистики (`durak.stats`). Резервная копия Android —
как в «Нардах» (ADR 0024 «Нард»): профиль онлайна возвращается только на тот же телефон.

Сделано к этапу Е — ключи `src/state/storage.ts`: `durak.current` (идущая партия с ботами), `durak.settings`,
`durak.crashlog`, `durak.device`, `durak.adult`, `durak.ads` (счётчики рекламы, `src/money/ads.ts`), `durak.purchases`
(кэш прав «Без рекламы», «Про» и купленных рубашек), `durak.unlocked` (разборы, открытые рекламой), `durak.rate` (когда
просили оценку), `durak.tryon` (примерка рубашки на одну партию: рубашка, партия, кончилась ли она — `src/money/tryon.ts`).
Выбранная рубашка — поле `back` настроек (`durak.settings`); о рубашках и покупках сервер не знает.
Настройки — `personalAds` с этапа Е.

1.0: настройки `newbie` («Подсказки для новичка», по умолчанию да) и `transferTold` (окно «Что такое перевод» уже
показано). Нового ключа и миграции нет: поле, которого нет в строке, — по умолчанию; но если в сохранённых настройках
нет `newbie`, а в `durak.games` есть партии, игрок пришёл из прошлой версии — `newbie` выключен, `transferTold` включён,
если среди партий есть переводная (`taughtBefore`, `src/state/settings.ts`).

Этап Д (0.5.0): `durak.games` — законченные партии с ботами, 200 последних (`FinishedGame`, `src/state/history.ts`):
запись партии, уровень, начало и конец, брал ли игрок подсказку, досчитанный разбор (`Review`, `src/bot/review.ts`);
`durak.puzzles` — задачи дня по номеру дня: попытки, решена ли, смотрел ли ответ (`src/state/puzzles.ts`). Уровень
`strong` (до 0.5.0) в сохранениях и истории читается как `master` (`levelOf`).

Разные уровни ботов (после 0.8.0, просьба владельца 09.11.2026): уровень теперь — у каждого места бота.
- `durak.settings`, `choice`: `{ variant, bots, level, mixed, levels }` — `level` общий, `mixed` — «Разные уровни»,
  `levels` — три уровня по местам ботов 1–3 (помнятся, даже когда ботов меньше); что играет — `botLevels`
  (`src/state/settings.ts`). В строке прошлых версий нет `mixed` и `levels` — по умолчанию по полю: выключено, у всех
  `level`. Первый запуск — как был: подкидной, один бот, «Начинающий».
- `durak.current` (`SavedGame`): `{ record, levels, history }`, `levels` — по местам 1 … seats − 1. Незаконченную
  партию прошлой версии (одно поле `level`) **не переносим** — решение владельца 09.11.2026: она стирается молча, без
  записи в журнал сбоев (`isOldSave`), в меню просто нет «Продолжить партию». Это не забытая миграция по правилу устава
  «Сохранение — снимок с версией схемы и миграциями»: потерять можно только одну недоигранную партию, и владелец
  решил так.
- `durak.games` (`FinishedGame`): `levels` по местам вместо `level`. Записи прошлых версий с одним `level` читаются
  как «у всех ботов этот уровень» — по умолчанию при чтении, файл не переписывается; статистика игрока не теряется.
  Статистика по уровням — только столы одного уровня, разные — строкой «Разные уровни» (`Stats.mixed`).

Подробная статистика (решение владельца 09.11.2026, [`09-game-design.md`](09-game-design.md), «Статистика») — тоже
без нового ключа и без миграции: всё выводится из `durak.games` при открытии экрана (`src/state/stats.ts`, чистые
функции). Одна запись переигрывается один раз (`replayed`): по местам — отбоев сыграно, сколько раз брали, переводов,
козырей пришло из колоды, козырей в руке в конце, в каком отбое вышли (`exitBout`; оставшийся с картами — позже всех).
Из этого и из `levels`, `hinted`, `review` — `GameFacts` одной партии: место (`first` · `out` · `draw` · `fool`),
против каждого бота (`before` · `together` · `after`), ошибки и неточности разбора (`null`, если разбора нет). Из
списка `GameFacts` — `Stats`: места в целом, форма последних 20, против уровней (каждый бот отдельно, столы с разными
уровнями тоже), средние за партию с ходом (последние 10 против прежних, с 20 партий), четыре недели с понедельника,
рейтинг тренировок по партиям. 200 партий переигрываются быстрее, чем открывается экран (тест
`tools/test/charts.test.ts`); хранить выведенное рядом с записью незачем. Записи прошлых версий читаются как раньше:
без разбора — без строк ошибок, с одним `level` — «у всех ботов этот уровень».

## Сервер

SQLite (WAL), как в «Нардах»; миграции — `server/src/schema.ts` (номер — `PRAGMA user_version`, новые — только в
конец). Сделано в этапе Г:

| Таблица | Что |
|---|---|
| `players` | профиль: хеш ключа устройства, ник, тег, когда создан и когда был на связи |
| `ratings` | Glicko-2 по вариантам (`player`, `variant`, рейтинг, отклонение, волатильность, число партий) |
| `tables` | стол: код, вид (`friend`/`quick`), создатель, вариант, мест, уровень ботов на свободные места, состояние, номер текущей партии, `version`, `throw_order` — «Подкидывать» (миграция 2; столы до неё — `free`) |
| `table_seats` | место: игрок или бот (уровень). До начала у стола с ботами место без человека — за ботом своего уровня (хозяин меняет); сел человек — `bot` стирается, пересел — прежнему месту снова уровень ботов стола |
| `games` | партия: зерно сервера и его отпечаток, зёрна мест, первый ход, действия (JSON по порядку), запас часов мест, кто нажал «Реванш», итог, начало и конец |
| `reports` | отчёты «Сообщить об ошибке», 180 дней |

Позиция партии в базе не хранится: её даёт переигрывание действий от колоды (`restore` при запуске, ADR 0002). В
памяти — позиция, таймеры, кто в сети и кто играет за кого. Сроки хранения: стол, где никто не сел, — сутки;
законченные столы — 30 дней.
